# 真实深蹲视频的主机链路验证（2026-10-29）

**当前模型与门限的组合没有统计出本片段中可见的深蹲动作：65帧均因置信度不足被拒绝，累计0次。** 这是完整真实像素链路的负面可用性结果，不是已经完成运动识别的证明。没有修改模型、置信度或时序门限，没有使用合成关节点，也没有操作物理摄像头、开发板或音频。

## 输入与构建

输入来自 TensorFlow.js 官方仓库的 [pose_squats.mp4](https://github.com/tensorflow/tfjs-models/blob/c731b9ebbd6f4c9e8bf99b0df76bbdbf9c25b07f/pose-detection/test_data/pose_squats.mp4)：

- 仓库版本：`c731b9ebbd6f4c9e8bf99b0df76bbdbf9c25b07f`。
- 视频SHA-256：`ea9151e447b301985d5d65666551ef863b369a2e0f3a71ddd58abef2e722f96a`，508,341字节。
- 原视频720×1280，13秒、5fps，共65帧；保留原始PTS：0、200、…、12800毫秒。
- FFmpeg按比例缩放到135×240，左右补黑92/93像素，生成320×240、stride640的RGB565_BE。没有拉伸人体；这是视频派生的横屏相机输入，不能代表实际Mini3相机的曝光、色彩或取景。
- 逐帧字节数与SHA均在执行前按索引验证，完整索引保存在忽略缓存 `.cache/research-pose/tfjs-exercise/squats-rgb565be/index.json`。

目视联系图可见两次完整下蹲/起身，末尾还有一次未起身的下蹲。这只是非正式视觉参照，没有人工标注关节点、动作边界或正式计数标签。随视频存在的33点JSON未用作输入、训练材料或真值。

实际执行路径为：

`RGB565_BE 320×240 → 生产 pi_prepare → 源码构建的 pose_engine/TFLite Micro CNN → 生产17点C解码器 → ps_update(ML_SQUAT)`

同一个引擎和会话贯穿全部65帧。四头模型SHA为 `9051a5ceebc1eb5f535c1b1afe58d33ce878bf9358a159cbfc689c1abebf9c68`。模型输入仍为192×192，输出保持17个COCO关节点。

本次链接当前仓库的 `firmware/pose_runtime` 源码目标：pose库私有 `NDEBUG`，常规单元 `-Os`，普通/深度卷积翻译单元末尾追加 `-O3`，保持 `-fno-fast-math -ffp-contract=off`。从实际 `compile_commands.json` 检查这些设置；源文件、编译命令与可执行文件哈希记在本地报告。没有使用预计算关节点替代CNN。

## 时间契约与结果

采集时间使用 `capture_ms = 1000 + 视频PTS`；帧间隔真实保持200毫秒。主会话人为设定 `processed_ms = capture_ms + 100`，用于把图像/计数语义与硬件推理速度分开。**100毫秒是显式合成的处理年龄，不是开发板或桌面推理耗时。** 同时另开一个会话，将相同真实推理结果按401毫秒年龄送入，验证过期帧路径。

生产条件保持不变：关节点置信度0.60、最大帧间隔/年龄400毫秒，以及原有驻留、完整动作和连续性检查。

| 核验项目 | 结果 |
| --- | --- |
| 真实帧完成预处理、CNN和解码 | 65/65 |
| 主会话，合成100ms年龄 | 65帧均 `low_confidence`；0次完成事件，累计0次 |
| 状态机进展 | 所有帧保持 `WAIT_TOP`；未接受角度或部分动作周期 |
| 合成401ms年龄对照 | 65帧均 `too_slow`，累计0次 |
| 源码TFLM实际arena使用 | 1,945,552字节；传入容量2MiB |
| 参考数值核验 | 第0/16/32/48/64帧全部逐字节/逐float一致 |

最后一项使用未改写完整原模型，在隔离的 `ai-edge-litert==2.3.0` 中以 `BUILTIN_REF`、单线程、无delegate执行相同的实际C预处理输入。五帧的四个INT8预测头逐字节一致，51个解码float32也逐项完全一致。因此这些抽查帧上的拒绝不能归因于新的Release/O3优化改变了算术结果。

深蹲每侧需要肩、髋、膝、踝四个点同时达到0.60。65帧中，“较好一侧的最低分”范围为0.29907–0.56946，中位数0.43017，没有一帧具备完整合格侧。左肩未达标61/65帧，左右髋各59/65帧，右踝63/65帧。各点仍保留原始坐标与分数，没有为了通过测试更改阈值。

主机invoke测量中位数约140ms，最大约168ms，只是这次x86 Linux运行的CNN耗时；它没有用于替换视频PTS或绕过新鲜度检查，**不能换算成Mini3帧率**。

## 能说明什么、不能说明什么

本实验说明真实像素可以到达当前生产计数入口，低置信度和过期观测不会凭空产生次数。它也直接揭示了当前组合在此片段上的漏计问题，不能把“安全拒绝”描述为健身功能已经可用。

低置信度本身**不证明关节点坐标错误或模型准确率差**：这里没有人工关节点真值。竖屏内容先补成横屏，再经生产预处理补成方形；人体在输入中的覆盖比例、采样与量化，以及门限是否适合模型分数分布，都需要独立验证。单个人、单个片段不能决定哪种调整能够泛化。

后续应在有标注的多人物、多动作、遮挡与无动作片段上校准和验证，再结合实际Mini3输入与时延检查。不要仅为了让这个片段通过而降低置信度或放宽400ms限制。
