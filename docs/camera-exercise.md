# Mini3 摄像头运动候选版

此版本把 Mini3 板载摄像头、MoveNet 四头 CPU 推理、17 点解码、动作计数和 Lua 运动页面连在一起。它仍是**未上板的候选固件**：主机测试及交叉编译不能证明板上帧率、动作准确率、相机颜色顺序或内存余量。按当前静默要求，只做离线验收，实机演示另行进行。

**当前模型还不适合实时计数。** [静态性能审计](pose-performance.md)确认：在 300 MHz、最多双发射、零等待等宽松假设下，新的优化版仅普通卷积部分仍有约 5.05 秒/帧的条件下限，明显超过 400 ms 的有效采样门槛。这不是板端测速；原始调试版的约 18.94 秒只保留为历史证据。还需要更小且经过真实动作验证的姿态模型。

## 操作与奖励

首页「休息」进入休息中心，可选择提醒或运动。运动页面选择深蹲/俯卧撑，双击开始后才申请摄像头；停止或离开页面会取消会话。普通桌搭固件没有 `motion` 接口，页面显示不可用，不制造演示计数。

每个会话累计 5 次经原生算法确认的完整动作奖励 1 碗米饭，不跨会话拼凑不足 5 次的余额。原生累计数和会话 ID 是唯一计数来源；按键、计时和画面刷新不增加动作。奖励采用累计水位去重，并与库存放在同一份存档中。v2 存档使用 26 个标量，原先 9 个散步权益字段打包为有界字符串，保留旧存档权益；恢复存档不会打开摄像头。

## 原生生命周期

`motion.start(kind, session_id)` 接受 `pushup` 或 `squat`；返回 true 只表示异步启动已接收。Lua 随后轮询 `motion.status()` 的 state、reason、session_id、kind、reps、frame_ms、inference_ms 和可选 17 点。只有 `running` 的当前会话可以兑换奖励。停止后晚到的结果不能更新新会话。

VM 激活只授权启动，不创建任务或分配推理内存。显式开始后，低优先级工作任务先校验 Flash 模型描述头和实际 SHA-256，再初始化相机并确认 320×240 尺寸，之后申请 2 MiB arena、上下文和 RGB565 输出缓冲；全部准备成功才进入 running 和首次采集。相机配置期间短暂需要两张 VGA 缓冲，共 1,228,800 B，缩小后为 307,200 B；先完成这次缩小可避免它与大块 arena 叠加。推理不在 Lua/LVGL 线程中执行，工作任务也不调用 Lua/LVGL。

固定 SDK 的公共分配器在内存不足时可能触发全局 trap。运动缓冲改用其有锁、返回 NULL 的 `heap_caps_aligned_alloc_base`，不修改全局错误钩子。工作任务、任务队列、相机帧队列和租用锁使用调用方提供的 FreeRTOS 存储；相机驱动的分配/释放调用仅在 `CONFIG_RICESTEP_POSE` 下适配，原有传感器、DMA 和排队流程保留。这里依赖固定版本的私有堆接口，升级 SDK 时必须重新检查；并不意味着全系统所有分配都变为非致命。

取消使用递增代次；相机采集或推理返回后由原工作任务清理，不强删正在工作的线程或释放其在用缓冲。VM 停止、异常退出及替换都有独立原生取消路径，不能只依赖 Lua `on_exit()`。新会话须等前一次清理结束。

相机租用桥接所有原 service_camera 入口，阻止旧调用方在运动会话中改动相机。清理调用传感器设备生命周期释放帧缓冲/队列；保留 DVP 的常驻小型配置对象，重复初始化使用已核对的 SDK DMA 引用计数路径，拒绝不具备该路径的 `CONFIG_ARCS_GPDMA_DATA_ONLY` 配置。无法确认安全停止时隔离相机并拒绝重试；错误跨取消代次保留，不能误显示“已停止”。实际 DMA 停止行为尚待硬件验证。

每次会话结束释放大块推理与图像内存；首次开始后的小型任务队列、16 KiB 工作栈和服务互斥锁保持待机，不反复创建线程。

## 计数边界

动作算法要求同一侧关节、置信度、合理躯干几何、上下位停留和完整运动周期。姿态会话把模型坐标映射回原图，拒绝 padding、遮挡、异常坐标、位置/尺度突变、重复/倒序帧和不连续采样。几何连续性标记不是身份识别，无法保证分辨位置相近的人替换，也不支持多人可靠计数。

保持 400 ms 的最大帧龄/采样间隔。SDK 没有传感器曝光时间，所以以开始采集的单调时间作为保守下界，把阻塞采集和推理耗时一并算入帧龄。若 CPU 太慢，显示 `too_slow` / `insufficient_sampling` 并拒绝计数，不通过放宽阈值制造可用假象。后续板上测试用于测清真实瓶颈，不将它当作当前大模型能达到门槛的承诺。

## 构建与资源配对

```powershell
node scripts/setup-pose-source.cjs --check-only
pwsh -File scripts/build-standalone.ps1 -PoseRuntime
```

这只生成文件，不操作设备。候选输出在 `dist/native/pose-runtime/`：CP、ELF、配置、验证报告、`resources.bin` 和 `paired-candidate.json`。包装器核对 CP 的实际 ELF/二进制、头校验和、链接函数、编译选项、只读布局元数据和全部资源哈希。CP 位于原 `0x600000` 分区，配套资源覆盖 `0x100000..0x600000`；boot/AP、OTA 暂存和 KV 边界不变。

此配置禁止 SDK 自动产生使用旧资源表的 combined hex、LPK、OTA 包，且关闭 OTA 写入。**不能把运行候选 CP 与原厂资源混用**，也不能把旧 `-PoseLinkCheck` 诊断 CP 与新资源包配对。恢复原厂时必须恢复 CP 与原资源；现有构建脚本没有加入烧写动作。

TFLM 与姿态组件使用私有 `NDEBUG` 发布配置，普通/深度卷积单元最后应用 `-O3`，保留 `-fno-fast-math` 和 `-ffp-contract=off`。模型 SHA 校验、格式和 shape 检查、生命周期错误返回及动作有效性判断使用显式逻辑，仍然执行。打包验证同时拒绝失效的优化选项、混用调试配置和泄漏到应用层的 `NDEBUG`；不修改 SDK 全局编译策略。

- 2026-10-29 私有发布配置/热内核优化后的完整 Mini3 候选编译、链接及配对检查通过：CP **2,697,524 B**，SHA-256 `31ca49598d2543a4a81da63905b12b713b9c70fcfda635cbc1f405272e7b628b`；Lua 60,097 B，14 个原语音文件逐字节未变。43 个姿态编译单元及 worker 的实际选项通过检查，安全分配适配器已在实际 ELF 中确认。模型位于单独资源窗口，未再复制一份进 CP。此尺寸/哈希仅对应这次构建，改动后必须重建。
- 优化配置的主机回归：106 项 wrapper/模型/生命周期检查通过；灰色、渐变、噪声及真实 RGB565 照片的四个输出头和 17 点结果逐字节保持一致。`-Os`/`-O3`、调试/发布的五组隔离实验记录在 `.cache/pose-opt-audit/`，不将主机测试或指令数变化当作板端帧率。
- `test-pose-session.ps1`：832 项合成输入检查，GCC/Clang 和 ASan+UBSan 通过；包括原图映射到完整俯卧撑/深蹲周期及异常拒绝。
- `test-romfs-relocation.ps1`：编译固定 SDK 的真实 ROMFS 解析器，原资源与新基址上的 90 个字体/表情文件逐字节一致。
- `test-pose-worker.ps1`：GCC/Clang 的工作任务替身测试各通过 2,183 项检查（分别编译 mbedTLS 2/3 入口），相机租用桥通过 414 项检查；涵盖阻塞阶段取消、部分分配失败、反复开始/结束、旧接口竞争和清理失败隔离。另用固定 SDK 的真实帧缓冲函数与新分配适配器通过 264 项检查，包括第二个队列失败、VGA 缩小期间失败、回滚与重复释放检测。独立内存适配器测试不链接公共致命分配入口。这里仍使用堆、队列调度、相机、推理和哈希替身，不是硬件或真实模型的性能证据。
