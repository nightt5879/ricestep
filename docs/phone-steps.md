# iPhone 真实步数 → 本机中继 → 肥鱼

这条接入路线使用 **iPhone“健康”中的真实步数**，让开发板显示和兑换。计步发生在手机上；它不是板载传感器计步，也不是用计时或按键生成步数。用户仍可选择后续增加独立运动传感器。

目前代码和本机协议测试已准备；**没有读取用户健康数据，尚未在实际 iPhone 上完成授权与端到端验证**。健康数据访问和首次发送要由用户在手机确认。

## 本机中继

需要 Node.js 20 或更新版本。进入仓库后运行：

```powershell
# 默认只监听本机，供本地开发测试：
node scripts/step-relay.cjs

# 手机、电脑、开发板在同一可信局域网时，显式使用电脑的局域网 IP：
node scripts/step-relay.cjs --host YOUR_PRIVATE_LAN_IP --port 8787 --write-local-config
```

`YOUR_PRIVATE_LAN_IP` 需替换成电脑实际的 `192.168.*.*`、`10.*.*.*` 或 `172.16–31.*.*` 地址；不要使用示例地址当成真实地址。默认不监听所有网卡，不开放公网，不自动修改 Windows 防火墙。

首次运行会生成 32 字节随机 token，保存到被 Git 忽略的 `.cache/step-relay-config.json`。启动窗口只向本机用户打印带 token 的接收 URL。这个 URL 同时供手机 POST、开发板 GET；不要贴到公开仓库或投稿视频。

`--write-local-config` 在保留其他字段的前提下，把设备需要的 `step_url` 写进被忽略的 `.local-config.json`，供本机构建使用。它不是可提交的共享配置。自动化启动可加 `--quiet`，不把 URL 打到日志。

本机中继必须保持运行，电脑不能睡眠；手机同步时需能访问该局域网地址。HTTP 不提供传输加密，因此这条开发接入仅用于自己的可信局域网。它不会自动发布外网服务。Ctrl+C 停止服务。

## iPhone 快捷指令配置草案

Apple 官方确认快捷指令有 **Find Health Samples** 查找动作，以及 **Get Contents of URL** 的 POST/JSON 请求能力。以下将中文动作名称同时用英文标识；具体中文名称、过滤字段和权限提示需要在用户当前 iOS 上确认。[查找和过滤动作](https://support.apple.com/en-euro/guide/shortcuts/apd3c845e881/ios)、[POST 和 JSON 请求](https://support.apple.com/en-euro/guide/shortcuts/apd58d46713f/ios)。

1. 在“快捷指令”中新建“给肥鱼同步步数”。添加“查找健康样本 / Find Health Samples”，健康类型选 **步数**，时间范围限定为手机本地时区的**今天零点到运行时刻**。不要写入或删除健康样本。
2. **只选一个实际计步来源**，例如当前这台 iPhone；若手机动作提供来源／设备过滤，使用对应字段。若当前动作无法筛选来源，先停止这一步，不要直接把所有设备的样本相加。需现场确认怎样取得单一来源或由系统聚合过的每日值后再继续。
3. 对选定来源的步数样本取数值并求和，得到非负整数 `total`。此处“获取健康样本详细信息 / Get Details of Health Samples”和统计求和的确切可用字段需在手机动作列表确认；不要把样本数量当作步数。先用“显示结果”核对该来源的今日总数。
4. 从同一个本地日期生成 `day`，格式为 `yyyy-MM-dd`，例如 `2026-10-27`。避免使用星期年 `YYYY`，也不要将 UTC 日期混入手机的本地日界线。
5. 添加 URL，内容使用本机服务打印的**完整私有 URL**。添加“获取 URL 内容 / Get Contents of URL”，方法选 **POST**，请求体选 **JSON**；新增数值字段 `total` 和文本字段 `day`，分别绑定前两步的结果。
6. 首次手动运行时，由用户确认读取**步数**和向**自己的这台电脑**发送的权限。请求内容只有该日总数和日期；不要附带原始样本、定位、心率或其他健康数据。首次联调保持手机解锁，不假定锁屏后台自动执行。
7. 收到 HTTP 200 后，结果应显示 `source: apple_health` 和同一日期/总数。随后让开发板主动刷新；再走一小段并重复同步，确认只增加新步数，不重复发饭。尚无手机数据时，设备应显示“未同步”，不能把无数据解释成 0 步。

Apple“健康”会对不同来源设优先级；**简单求和多个来源的原始样本不等同于“健康”界面的系统聚合值**，可能把手机和手表记录的同一段步行计算两次。本版要求固定单一来源；换来源之前需重新确定同步基线，不能直接把更大的合计数当新增步数。[Apple 的多来源处理说明](https://support.apple.com/en-ca/108779)。

## 协议

只有 `/api/steps?token=PRIVATE_TOKEN` 这一个接口，没有静态文件服务。GET 与 POST 都需要 token；没有 CORS 开放，浏览器 Origin 请求默认拒绝。接收体最大 2 KiB。

POST 请求体只有两个字段：

```json
{"total": 1234, "day": "2026-10-27"}
```

上面的数字仅说明格式，**不要把示例数字发送到真实游戏来声称完成健康数据联调**。`total` 必须是 0–200000 的整数，日期须是真实有效的 `YYYY-MM-DD`。同日总数只允许不变或增加；进入更晚日期后允许从小数值重新开始；旧日和同日倒退都返回 409。

有数据的 GET / 成功 POST 返回：

```json
{"total":1234,"day":"2026-10-27","source":"apple_health","updated_at":"2026-10-27T10:00:00.000Z"}
```

`updated_at` 是电脑接收的 UTC 时间，`day` 是手机负责提供的本地日期。首次尚未同步时 GET 返回 **204 空响应**。应用必须区分“未同步”和真实 0 步。

设备 GET 会附加 `fresh=1`：手机超过90秒未同步时返回204“等待最新同步”，不会把中继缓存误认为手机刚更新。散步可以在断网期间保持进行中，显示最近收到的步数；回家重新同步真实累计值后再结算。出发前和结束前各运行一次手机快捷指令。手动暂停／继续会重新建立累计步数基线，暂停期间不发奖励。

状态存于 `.cache/step-relay-state.json`，重启中继会恢复。中继校验格式与增量顺序，但它不会对 Apple 健康来源作密码学认证；来源可靠性依赖由用户配置、授权并核对的快捷指令。持有私有 URL 的人可以读写该总数，请保持它仅在本人设备上。

## 验证范围

```powershell
node --test tests/step-relay.test.cjs
```

测试使用临时目录、独立测试 token 和合成样本，覆盖授权、空状态、格式、大小限制、日界线、同日单调、重试、并发和持久化。测试不读取健康数据，也不能证明 iOS 快捷指令已经成功。实际手机授权、单一来源筛选和板上展示须另外完成。
