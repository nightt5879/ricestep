# 步数接入：保留方案，当前版本不启用

2026-10-27用户选择“桌面陪伴＋小游戏”。当前构建只包含喂饭、专注、煮饭和收藏：**不打包`app/step-sync.lua`，不读取`.local-config.json`，没有散步入口，也没有读取手机健康数据。** 启动中继服务本身不会让当前应用开始接收步数。

尚未找到这块Mini3可用的运动传感器或小应用传感器API，独立板载计步没有实现。仓库保留旧散步规则、`scripts/step-relay.cjs`、`app/step-sync.lua`及协议测试，供将来有真实来源时恢复；计时、按键和测试样本都不能冒充步数。

## 2026-10-27：板载硬件复核

用户再次要求核查板子本身。查看了[Mini3官方硬件说明](https://docs2.listenai.com/x/1KVekpl1e)及其链接的[开源硬件工程](https://oshwhub.com/lshuangyu/ling-si-arcs_mini-kai-fa-ban)：

- 官方部件表列出GC0328摄像头、麦克风、电池电压采样及充电检测；CH32V003是扩展GPIO／ADC／PWM的MCU，不是加速度计。
- 官方硬件资源与引脚表未列出加速度计、陀螺仪、IMU、计步器或GPS。“支持外部传感器扩展”不表示已经板载运动传感器。
- 开源工程页面可见“聆思ARCS_MINI_v3开发板”，但显示暂无BOM；本次未取得可逐器件检查的完整原理图。因此证据支持“未发现可直接用于计步的板载运动传感器”，不能扩大成“已完整核对原理图，绝无未标注传感器”。
- 之前对这块设备API5的实际全局探针没有sensor／imu／motion模块；本次复核公开LingClaw SDK接口目录也未找到运动传感器或I2C读写API。硬件上有I2C不等于当前Lua应用可读取。

要继续板子独立计步，先确认原理图／BOM或实际芯片丝印；如果确实无板载运动器件，再核对Mini3扩展引脚、外接加速度模块及底层固件驱动、Lua接口的实现途径。不能照搬Mini2接线。本次只读核查，没有刷固件或替换正在运行的陪伴应用。

## 保留的手机方案

原设计为iPhone“健康”→用户授权的快捷指令→电脑局域网中继→开发板。它尚未在实际iPhone上完成授权与端到端验证。恢复该路线需要重新接入界面与构建，并核对手机单一计步来源，避免把iPhone与手表的同一段步行重复相加。

中继只接受`/api/steps?token=PRIVATE_TOKEN`：POST JSON为`{"total":1234,"day":"2026-10-27"}`，GET返回已保存数据。例值仅说明协议，不代表测得步数。总数必须为0–200000的整数，同日只增不减，旧日期拒绝；无数据返回204。`fresh=1`要求90秒内有手机新同步，否则返回204。

默认仅监听本机；显式指定私有局域网IP才供其他设备访问。32字节随机token和步数状态仅保存在忽略的`.cache/`中，不开放公网，不自动修改防火墙。`--write-local-config`仍可写旧配置，但**当前构建忽略该文件**。

协议测试可单独执行：

```powershell
node --test tests/step-relay.test.cjs
```

测试使用隔离的合成数据，不读取健康信息。此前完整接入草案保留在[历史版本](https://github.com/nightt5879/ricestep/blob/9fe65e952716abeca12f5c2f7aa0ef5193a64e8a/docs/phone-steps.md)，不能直接当成当前版本操作说明。
