# MoveNet 缩小输入实验（仅主机，2026-10-29）

**结论：可以保留预训练权重、改写几何参数并执行完整 17 点模型；不能把它视为已经可用的实时运动模型。** 128/96 输入仍超过本轮约 20 MMAC 的优化候选预算；48/32 接近或低于该预算，但这张照片上的置信度下降，没有通过现有 0.60 关节点门限。没有替换生产模型、修改门限或操作开发板。

## 实际图变更

原始 Google MoveNet Lightning int8 v4 的 SHA-256 为 `cd7cc22fa946e5d146a7b98d496853e1923e22828d3972d579973f27f91bb105`。完整图是 157 个算子，输入 `[1,192,192,3]` UINT8，四个 CNN 头为 tensor 259/276/282/285，最终 tensor 332 为 `[1,1,17,3]` FLOAT32。

只调用 `resize_tensor_input()` 改输入，128 和96都会在 ADD 节点72失败：固定12×12放大输出与8×8或6×6跳接张量不能相加。因此本实验改写的是整个图的空间契约，不能称为原模型直接支持动态尺寸。

令输入边长为 `N`，输出网格为 `G=N/4`。实际改写如下：

| 对象 | 原始值 | 实验改写 |
| --- | --- | --- |
| tensor 1/2/3，RESIZE_BILINEAR 尺寸 | 12/24/48 | N/16、N/8、N/4 |
| 非常量 CNN 空间形状 | 各层原尺寸 | 按步幅向上取整；48输入最深层为2×2 |
| tensor 6，行索引除数 | 48 | G |
| tensor 154，中心先验 | 48×48×1 | G×G×1，按下式重新量化 |
| tensor 170/171，y/x网格 | 48×48×1 | G×G×1，坐标0…G−1，沿用原量化参数 |
| tensor 173，坐标归一化常量 | 1/48 | 1/G，仅改变其量化scale |
| 后处理空间及展平形状 | 48×48、2304 | G×G、G² |
| Signature 元数据 | 原192输入定义 | 从实验文件移除 |

中心先验采用 `quantize(1 / (sqrt((y−G/2)² + (x−G/2)²) + 1.8))`。在 G=48 时，它重建了原常量的全部2304个字节。将它推广到其他G是本实验推导的几何规则，**不是作者发布的缩小模型定义**。

全部普通卷积、深度卷积权重与偏置逐字节保持一致；除173外的所有tensor量化元数据也逐项保持一致。没有训练、剪枝或替换学习参数。四头通道仍为1/17/34/34，保留原17个COCO关节点语义。归一化、量化距离权重、argmax和偏移采样仍由修改后的完整原图执行，没有用普通热图argmax或自写浮点近似解码替代。

## 主机结果与数值核验

使用隔离的 `ai-edge-litert==2.3.0`，`BUILTIN_REF`、单线程、无delegate；Micro使用 `tflite-micro==0.dev20261026171606`。六个尺寸均完成完整图Invoke并返回有限的17×3结果。

192恒等改写在两种输入准备方式上与未改写原模型逐float一致。RGB565输入的192预处理还与生产C的 `pi_prepare` 逐字节一致；完整原模型输出与已保存的源码构建C++ TFLM基线逐float一致。96/48/32另行执行真正的主机TFLite Micro四头图，与完整LiteRT四头逐字节一致。

| 输入边长 | 卷积名义MAC | 排除padding的有效MAC | RGB565置信度中位数 | ≥0.60的点/17 | 与192坐标平均距离 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 192 | 270,549,504 | 269,525,360 | 0.43017 | 2 | 0 |
| 128 | 120,244,224 | 119,570,288 | 0.36462 | 0 | 0.13312 |
| 96 | 67,637,376 | 67,138,544 | 0.36462 | 0 | 0.09101 |
| 64 | 30,061,056 | 29,737,328 | 0.36462 | 0 | 0.10011 |
| 48 | 19,866,816 | 19,606,448 | 0.15568 | 0 | 0.14845 |
| 32 | 7,515,264 | 7,366,640 | 0.19665 | 0 | 0.08187 |

MAC按实际分配后的每层形状、步幅、膨胀和padding计算。48的最深层向上取整，故不能简单用192的运算量乘面积比。坐标距离是补边后归一化方形空间中，相对192输出的欧氏距离，**不是相对人体标注的误差**。

Micro allocator实际使用：96为615,232字节，48为282,592字节，32为220,992字节；传入的2MiB容量不是实际使用量。模型文件仍约2.89MB，因为降低分辨率没有减少学习参数。

## 限制与采用决定

只有一张独立照片：[TensorFlow.js公开测试图](https://github.com/tensorflow/tfjs-models/blob/c731b9ebbd6f4c9e8bf99b0df76bbdbf9c25b07f/pose-detection/test_data/pose.jpg)，JPEG SHA-256 `c8a830ed683c0276d713dd5aeda28f415f10cd6291972084a40d0d8b934ed62b`。两种准备方式是原始1000×667 RGB888，以及缩到320×213、在320×240画面y=13处补黑再转RGB565的同图派生版本，不能算两个独立样本。192基线也仅有2/17点达到0.60；不能据此推导数据集准确率、计数成功率或运动时序表现。

缩小输入改变人体相对感受野、边缘padding和采样失真，原有中心回归、局部偏移与激活量化范围未重新校准。完整图可运行和CNN数值一致，只验证导出链路，没有验证缩小后的视觉任务质量。

早先 `-Os` 参考内核中，每次普通卷积MAC有45条直接指令。在假设300MHz、最多双发射、零停顿时，48/32的普通卷积历史下界分别为1.4007/0.52555秒，未计深度卷积等工作。这些数字只对应**历史45指令循环**；当前另行集成的私有Release/O3内核必须重新检查ELF与计时，不能套用旧下界，也不能将它称为实测FPS。本实验的MAC和图形状结果不依赖该编译优化选择。

因此本次**不采用**这些模型。128/96没有解决运算量问题；48/32虽可作为后续训练或微调起点，却没有达到可可靠计数的证据。生产profile的模型hash与shape检查、固定48×48 C解码器会拒绝这些实验文件，应保持这些检查。下一步需要优化后内核的独立性能证据，以及有标注的多人物、多动作序列验证；不能通过降低置信度或放宽400ms门限掩盖问题。

## 复现与产物

独立脚本：[experiment_resolution.py](../scripts/pose/experiment_resolution.py)，不下载依赖或数据，不访问设备，输出目录必须在仓库 `.cache` 内。依赖和原始模型准备方式见 [现有探针说明](../scripts/pose/README.md)。RGB565 fixture及原生基线来自已执行的本地主机真实像素审计；这些忽略缓存不会随仓库分发，缺失时需按上述图像构造重新生成基线，本脚本不会伪造它们。

从WSL仓库目录运行：

```bash
python3 scripts/pose/experiment_resolution.py \
  --micro-path .cache/research-pose/tflm-host \
  --litert-path .cache/pose-oracle/litert \
  --output-dir .cache/pose-resolution
```

默认读取 `.cache/pose-oracle/pose.rgb`、`.cache/pose-real-audit/person-320x240.rgb565be`、`native-input-int8.bin`、`native-landmarks-f32.bin`，并核对固定公开图像数据的SHA。输出包含实验TFLite文件、逐点NPZ和JSON报告；allocator账目打印到日志。最初探索记录在 `.cache/pose-resize/`，整理后的复现输出在 `.cache/pose-resolution/`。模型、原图和生成二进制均不提交。
