# 后续方向：健身赚饭，肥鱼陪练

记录于2026-10-27。用户提出用摄像头观察身体动作，识别俯卧撑、波比跳等运动，完成动作赚大米饭，再喂给肥鱼。这是后续构想；当前版本仍是桌面陪伴、喂饭、专注、煮饭与收藏，**尚未实现摄像头取帧、人体姿态识别或运动计数**。

## 想要的体验

用户主动开始一次练习，摄像头画面用于识别完整动作；确认次数后兑换米饭，肥鱼用蠢萌的声音和表情回应。例如：“你又做完一个？那我的饭，也多一口。”兑换比例、单次目标与台词后续再定。

拟议流程：摄像头画面 → 人体姿态／动作阶段 → 完整动作计数 → 一次性结算米饭 → 肥鱼反馈。

## 先验证什么

1. **先取得真实画面。** 现有硬件资料列出Mini3配有GC0328摄像头，但这不等于当前Lua小应用能取帧，更不等于板上已有姿态模型。先核对固件3.1.0/API5的摄像头接口、可用分辨率与传输方式，并验证实际画面；证据见[硬件复核记录](phone-steps.md)。
2. **确定推理在哪里运行。** 只有在取帧与运行资源均得到验证后，才评估板端识别。若当前Lua不支持取帧，电脑摄像头＋电脑侧识别、Mini3接收计数并反馈可以作为备选；是否接受依赖电脑，由后续讨论决定。暂不承诺开发板可以独立完成识别。
3. **先做俯卧撑一个动作。** 明确机位和可见身体范围，用连续状态区分准备、下降、低点、回到起始位置；完成完整循环才计一次。置信度不足、身体离开画面、仅保持姿势或只做半程时，不自动增加次数。先拿真实动作与人工计数对照。
4. **再扩展波比跳。** 波比跳包含下蹲、支撑、收腿、起身／跳起等多个阶段，要先约定计数动作的具体版本，再验证阶段顺序与遮挡恢复，不能只按跳跃或画面变化次数计算。
5. **最后接入奖励。** 为每次练习和结算记录唯一标识，防止重复消息、重新连接或重载导致重复发饭；米饭奖励与识别状态分开。先确认现有30字段／1KiB存档还能容纳哪些数据，再决定会话记录保存在哪里。

## 验收边界

需要分别验证正常完成、半程、暂停、出画／遮挡、第二个人入画、重复结算及断线恢复。演示数据必须标为模拟；没有真实摄像头识别证据时，不展示成已经测得的运动次数。

实现前不启用摄像头，也不采集或保存影像。当前“运动赚饭”构想不改变已经可玩的肥鱼饭搭子版本。
