# 摄像头运动界面与奖励账本

「休息→运动」提供俯卧撑／深蹲选择，进入页面不会开启摄像头，必须双击
「开始」。运行中可停止或返回；离开页面、应用退出都会停止原生会话。
重启不恢复摄像头，异常或已经停止的会话也不会因为后续状态重新启动。
没有原生接口时显示「当前固件未开放摄像头」，不会用计时、按键或演示
数据冒充动作。尚未完成实机摄像头与动作效果验收。

Lua 不执行姿态推理或动作计数，只接收原生 `motion` 接口的状态：

```text
motion.start("pushup" | "squat", positive_session_id) → true | false, reason
motion.stop()
motion.status() → {state, session_id, kind, reps, reason, points?}
```

状态为 `unavailable/idle/starting/running/stopping/error`。有效调用遇到
摄像头、模型或资源问题必须返回失败／error状态，不能抛出 Lua 错误；
官方沙箱没有 `pcall`。开始返回 busy/false 时不消耗会话编号。开始被接受
后才提交编号，异步失败会结束该编号，不撤销已确认的奖励也不恢复会话。

只有当前显式会话的 `running` 状态，且编号、动作类型匹配时，才接受
非负整数累计 `reps`。重复、倒序、其他会话、其他动作、非法数值以及
starting/error计数全部不奖励。每累计5次获得1碗饭，跨多次轮询按增量
发放。不同会话不合并不足5次的余数。库存已满时仍推进处理水位，防止
随后喂饭再重放旧计数来领取额外奖励。整个流程不增加步数。

界面只画原生返回的17个COCO关键点；坐标必须是原图归一化x/y，置信度
低于0.5、非有限或越界点不显示。预览按原生 `image_aspect` 等比例居中，
缺少或无效的宽高比不显示关键点。俯卧撑与深蹲均要求侧身全身入镜。
识别过慢、采样不足、画面中断或顺序异常会明确提示，不用鼓励文字掩盖。
这不是摄像头照片，也不会合成未检测到的身体。原生层负责时间戳、
置信度、动作完整性、遮挡重置和相同人的连续性，Lua不会根据关键点补数。

## 存档v2

v1仍可读取。v2把旧散步的 `status/source/elapsed_ms/step_count/session_id/
claimed_id/pending_item/timer_carry/step_carry` 九个字段，按固定顺序以 `|`
连接保存到 `walk` 字符串中；所有旧计时、步数余数、未结算奖励和待领取
收藏均保留。其他宠物、专注、饭锅记忆、提醒字段保持原义。

新增 `exercise_id` 和 `exercise_reps` 是最近已接受会话及其已处理累计
计数。它们与米饭余额在**同一份export、同一次存档**写入；游戏不另外
写奖励水位。保存失败时，旧余额和旧水位一起保留；重启时不会单独恢复
未保存奖励。突然断电可能丢失最近不足10秒的未保存进度。

导出共26个标量，单个字符串不超过256字节、JSON不超过1KiB。测试覆盖
最大数值宽度、v1→v2完整权益往返、重复／倒序状态、库存上限、拒绝启动、
异步失败、退出取消、重启与保存失败。行为测试使用测试文件内的模拟
原生状态且关闭声音；API4/API5的完整角色绘制和界面预算另行测试。
