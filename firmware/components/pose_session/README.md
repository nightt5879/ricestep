# 单人姿态到运动会话

`pose_session` 将 MoveNet 解码后的 17 点，经 `pi_unletterbox` 还原到原始相机画面，再交给 `motion_logic`。它只做内存中的同步处理，不读取相机、时钟、文件、网络或音频，不分配堆内存，也不写米饭奖励。

## 调用契约

1. `ps_start(&session, ML_PUSHUP / ML_SQUAT, session_id)` 初始化一个会话。ID 非零；调用方负责持久、递增的会话 ID 和奖励去重。
2. 每帧调用 `ps_update(&session, landmarks, &transform, capture_ms, processed_ms)`。`transform` 必须对应这帧的 `pi_prepare` 输出。两个时间参数都是同一单调时钟的毫秒时间戳；`processed_ms` 是消费推理结果的时刻，**不是耗时**。
3. `result.exercise` 是累计计数、阶段、底层原因、当前角度和 `rep_completed`。仅当 `rep_completed` 为真，调用方才可考虑一次新的奖励；不可根据某个姿态、累计值重复出现或 token 变化发奖。
4. `ps_stop()` 取消尚未完成的动作，保留本会话已完成的计数；之后 update 不再运行运动状态机。新 start 建立新会话，计数归零。

`points[17]` 为原始画面归一化 x/y/confidence；`valid_points` 是有效点位图。非有限坐标、padding/画面外点、低于 0.60 或大于 1 的置信度均变为零置信度。不做坐标夹取、镜像或旋转。缺失面部等非必需点不必丢弃整个身体，但运动所需的一整侧肩/髋/膝/踝，以及俯卧撑的肘/腕，必须全部可用。映射失败的点不会用前一帧补齐。

## 时间与欠采样

使用原有 `ml_exercise_defaults()`，包括 **400 ms 最大帧间隔**、180 ms 停留、900 ms 最小动作时间；不提供为了慢推理而放宽的开关。

| 情况 | 结果 |
| --- | --- |
| 结果消费时刻减采集时刻大于 400 ms | `too_slow`，包括慢推理或积压的旧帧 |
| 相邻采集时间间隔大于 400 ms | `insufficient_sampling` |
| 重复采集时间 | `duplicate_frame` |
| 采集时间或结果消费时间倒退 | `out_of_order` |
| 采集时间在消费时刻之后，或差值超出半个 uint32 范围 | `invalid_time` |

上述情况全部取消当前半次动作、使连续观测 token 失效，不增加计数。**停留与动作时长只用采集时间**，不能因推理完成得晚而凑够最短动作时长。支持 uint32 时钟正常回绕；不同进程/设备的时钟不能混用。长时间无任何帧时没有自动时钟推进；下一帧会检测间隔并重置。

SDK 如果没有曝光/传感器时间戳，调用方可以使用进入采集函数前的单调时刻作为保守的采集时间下界，令等待/丢帧/读取耗时都计入帧龄。必须明确记录它不是实际曝光时间。只记录采集函数返回时刻，会掩盖在采集过程中变旧的图像。

若板端真实耗时持续超过限制，这个模块会持续报告不可用采样；不能把重复姿态或漏掉的运动补算成次数。需要实际测量后改进推理/采集性能，或重新评估产品交互。

## 连续观测的保守检查

每次有效观测选择一整侧运动链，之后保持该侧。使用该侧肩与髋的中点和躯干长度，x 距离先乘原图宽高比，使比较单位一致。相邻有效帧出现以下情况会中断：

- 肩髋中点移动超过上一帧躯干长度的 0.75 倍。
- 躯干长度比例超出 `[1 / 1.4, 1.4]`。
- 原图宽高比变化、原先一侧不可用、所需关节点缺失或运动几何不成立。

这些是尚未经过真人相机验证的保守几何阈值，可能拒绝快速运动。完整动作仍须经过 `motion_logic` 的顶端停留、下降、底端停留、返回顶端停留及时间条件。

`continuity_token` 只标识一段**连续、几何上合理的单人观测**。失去观测时输出 0；下一段有效观测递增 token；计数器耗尽时拒绝继续分配。token 仅在本次 session 内有效，经 `ml_pose.subject_id` 传入底层只是为了中断动作，**不表示身份识别**。

这个模型与接口不提供多人跟踪，无法排除另一人以近似姿态接替、多人重叠、相似位置中的模型选人变化，或背景误检。逐帧缓慢漂移也不会被当成确定的换人。当前使用前提是画面内只有一人、运动链完整可见；不能声称已经解决身份连续性或防作弊。

## 主机验证

```powershell
pwsh -NoProfile -File scripts/test-pose-session.ps1
pwsh -NoProfile -File scripts/test-pose-session.ps1 -Compiler 'C:\Program Files\LLVM\bin\clang.exe'
```

独立 CMake 测试入口是 `tests/native/pose_session`，无需 TFLM 或模型文件。测试从实际 RGB565 `pi_prepare` 生成 transform，再将合成关节点送过完整映射/会话/计数链。覆盖三种宽高比的俯卧撑与深蹲完整/部分动作、遮挡、NaN/Infinity/padding、位移/尺度/侧别/画幅突变、旧帧/乱序/长间隔、采集时间与完成时间分离、取消、重新开始和时钟回绕。

2026-10-29：Windows GCC 与 Clang 均通过 832 项检查；WSL GCC 的 AddressSanitizer + UndefinedBehaviorSanitizer 构建同样通过全部 832 项，无 sanitizer 报错。

这些测试证明代码和合成输入的状态转换；不证明板端实时性、摄像头人体识别精度或真人健身效果。
